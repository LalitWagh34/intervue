INTERVUE WEBSITE REVIEW AND ANTIGRAVITY IMPLEMENTATION PLAN
Reviewed: 2026-11-21
Scope: repository inspection of React/Vite web app, Hono/Bun API, Prisma schema, deployment config, existing tests. This is a source-level review; authenticated production browser flows and live integrations were not exercised. An item marked "verify" needs a reproduction before changing behavior. Existing uncommitted learning/rooms/database work was left untouched.
Baseline: web build passed with one chunk-size warning; web tests passed (14 files, 36 tests); server tests passed (106 tests) only with a dummy GROQ_API_KEY, while the no-key run failed at import. These results describe the current worktree, including pre-existing uncommitted changes.

PRIORITY KEY: P0 = security/data integrity; P1 = broken or misleading core flow; P2 = usability/performance/maintainability; P3 = polish.

FINDINGS AND CORRECT IMPLEMENTATIONS

SECURITY AND DATA PROTECTION
01 [P0][confirmed] CORS reflects any Origin while credentials are enabled. Evidence: apps/server/src/index.ts, cors origin callback ends with `return origin`; `origin.startsWith(allowed)` also permits lookalike origins. Correct: compare parsed origin exactly against a configured allowlist; fail closed for unknown origins; allow localhost only in development; add hostile-origin preflight tests.
02 [P0][confirmed] Auth trustedOrigins dynamically accepts arbitrary *.vercel.app and callback-derived origins; account linking skips state cookie check. Evidence: apps/server/src/lib/auth.ts. Correct: restrict to owned deployment origins, remove callback-based trust expansion, review and enable OAuth state validation; test cross-site and redirect behavior.
03 [P0][confirmed] Session token is appended to OAuth redirect URL then stored in localStorage. Evidence: apps/server/src/index.ts and apps/web/src/lib/auth.ts/api.ts. Query tokens can enter browser history, logs and referrers; storage is readable by injected script. Correct: use an owned same-site auth callback and Secure/HttpOnly/SameSite cookie; if cross-site exchange is required, use a short-lived one-time code exchanged server-side, then clear URL before loading app. Recheck mobile Safari with real devices.
04 [P0][confirmed] Authenticated code job GET and DELETE lack `job.userId === c.get('user').id`. Evidence: apps/server/src/routes/code.ts /jobs/:id; queue jobs contain userId in apps/server/src/services/taskQueue.ts. Correct: owner-check before returning results or canceling; use 404 for another user's job; add two-user tests. Also restrict /queue-stats to admin or expose only safe aggregates.
05 [P0][confirmed] Feedback email HTML interpolates untrusted name, email, subject and message without escaping. Evidence: apps/server/src/routes/feedback.ts. Correct: HTML escape every interpolated value or use a text-only email/template renderer; validate addresses and lengths with a schema; persist first, dispatch via bounded background task; never echo internal exception text.
06 [P1][confirmed] Voice STT accepts an unbounded uploaded File and TTS accepts unbounded text, and TTS returns upstream bytes as audio even on error. Evidence: apps/server/src/routes/voice.ts. Correct: validate MIME, size, duration/text length; apply per-user cost limits and request timeout; verify upstream status/content type; return JSON errors for failures.
07 [P1][confirmed] Resume parser reads the full upload into memory before checking file type/size, and returns exception messages. Evidence: apps/server/src/routes/interview.ts /parse-resume. Correct: cap request/file bytes before parsing, permit explicit PDF/TXT types, limit extracted text, reject malformed files, redact internal failures and define retention/deletion for resume data.
08 [P1][verify] Room participant details, spectator snapshots and code streams need an endpoint-by-endpoint authorization matrix. Evidence: apps/server/src/routes/rooms.ts /:code, /leaderboard, /scorecard, /participant-code and apps/server/src/services/roomSocket.ts. Existing revocation tests cover some paths. Correct: require current membership or authorized host for private views, hide solutions during active contests per product rules, revoke immediately after kick/leave, test cross-room and disconnected users.
09 [P1][verify] Anti-cheat evidence is browser-supplied (visibility, blur, paste); treating it as conclusive proof risks unfair disqualification and false positives. Evidence: apps/web/src/hooks/useAntiCheat.ts and roomSocket service. Correct: state exactly what is monitored, debounce/deduplicate incidents, allow appeal/review, keep server-controlled penalties, and avoid claiming tamper-proof proctoring.
10 [P1][confirmed] Rate limiter keys anonymous users from raw x-forwarded-for, which clients may forge unless the trusted proxy normalizes it. Evidence: apps/server/src/middleware/rateLimiter.ts. Correct: use a trusted platform IP header/proxy configuration; apply global limits to search, auth-adjacent, uploads and expensive AI routes; choose explicit fail behavior when Redis is unavailable.
11 [P1][verify] Security headers are not configured in Vercel or Hono response middleware. Evidence: apps/web/vercel.json and apps/server/src/index.ts. Correct: add CSP calibrated for Monaco/WASM/OAuth, HSTS on HTTPS, nosniff, referrer policy and suitable permissions policy; regression-test sign-in, editor and voice assets.

CORE PRODUCT AND DATA CORRECTNESS
12 [P0][confirmed] Daily reward uses read-check-write and sets points from a stale value; concurrent requests can double-claim or lose points. Evidence: apps/server/src/routes/rewards.ts /daily-checkin. Correct: DB transaction plus conditional update/unique claim per user and date; atomic increment; define timezone rule; concurrent request test.
13 [P1][confirmed] Sheets endpoint invents 1,420 users on DB failure/empty DB and computes `activeThisMonth` from a formula. Evidence: apps/server/src/routes/sheets.ts. Correct: query real aggregates or omit unavailable stats; show unknown/temporarily unavailable UI state; never present derived marketing numbers as measured metrics.
14 [P1][confirmed] Practice solved state can fall back to account-agnostic `tuf_solved_problems` localStorage after API failure. Evidence: apps/web/src/pages/PracticeHubPage.tsx. Correct: key cache by account, label offline state, reconcile with server on reconnect, clear on logout/account switch, use one canonical problem ID and React Query mutation rollback.
15 [P1][confirmed] Coding route and voice route exist as pages but are disabled/redirected. Evidence: apps/web/src/App.tsx; CodingPage.tsx, VoiceInterviewPage.tsx. Correct: decide supported V1 scope; either integrate and test complete flows or remove related navigation, assets, claims and code; update README/product tour accordingly.
16 [P1][verify] Landing/README claim feature breadth and metrics that may not match enabled routes or actual seeded content, including voice/coding and 470+ company archive. Evidence: README.md and apps/web/src/pages/LandingPage.tsx versus App.tsx. Correct: audit each claim against a working route and real data count; render measured values from API; remove unsupported promises.
17 [P1][confirmed] Interview evaluation is launched as an unawaited in-process promise after ending a session; a restart can lose it. Evidence: apps/server/src/routes/interview.ts /:id/end. Correct: persist evaluation state and enqueue durable background job with retries/idempotency; expose pending/failed/retry in ResultsPage; ensure only one evaluation per interview.
18 [P1][verify] Chat/interview histories are loaded without visible pagination/windowing in route queries, and long conversations raise DB, token and rendering cost. Evidence: apps/server/src/routes/chat.ts and interview.ts. Correct: cursor pagination for lists/messages, bounded model context with summary, server-side token budget, visible history loading in UI.
19 [P1][verify] Room MCQ re-answer and score update use separate DB operations; simultaneous answers may lead to incorrect score. Evidence: apps/server/src/routes/rooms.ts /:code/mcq-answer. Correct: transaction/unique answer row with consistent delta, lock or conditional versioning; concurrent double-submit test and replay/idempotency handling.
20 [P1][verify] Room code generation and question selection use Math.random; code uniqueness is checked before insert. Evidence: apps/server/src/routes/rooms.ts. Correct: cryptographic random room code with DB unique constraint/retry on conflict; deterministic seeded selection only where repeatability matters; test collisions and insufficient pools.
21 [P1][verify] External platform sync and readiness calculations need explicit freshness and error states. Evidence: apps/server/src/routes/profile.ts, lib/externalStats.ts, apps/web/src/hooks/useProfile.ts/useReadiness.ts. Correct: persist fetched-at and per-provider status, set timeouts/retries, show stale data clearly, and preserve previous verified values on provider failure.
22 [P1][verify] Learning revisions/content are being edited in the current worktree. Evidence: modified learn routes, admin editor, schema/package and new manifest/backfill files in git status. Correct: finish and verify revision publication invariants, migration/backfill, progress scheduling and rollback in isolation before relying on content counts; avoid overwriting work in progress.

FRONTEND, UX AND ACCESSIBILITY

Evidence: apps/web/src/App.tsx, components/shared/CommandPalette.tsx, apps/server/src/routes/search.ts. Correct: render palette for intended users, filter published items server-side, rate-limit/debounce/cancel requests, provide error/retry state and navigate to an actual result destination.

25 [P1][confirmed] Command palette overlay uses a plain div and click backdrop rather than an accessible dialog with focus trap/restore. Evidence: CommandPalette.tsx. Correct: use Radix Dialog or equivalent with aria-label, Escape, inert background and focus return; keep cmdk keyboard semantics.
26 [P1][verify] Complex rooms, interview, chat and admin screens need keyboard and mobile audits. Evidence: large page components under apps/web/src/pages and rooms. Correct: test 320/375/768/desktop widths, keyboard-only flows, 200% zoom, focus order, dialogs, forms and live announcements; fix specific failures instead of blanket CSS edits.
27 [P1][verify] Loading/empty/error states are inconsistent across data-rich pages and several catches silently ignore failures. Evidence: App.tsx prewarm, PracticeHubPage, NotepadPage, TargetCompanyTracker, hooks. Correct: reusable loading/empty/error/retry components with actionable copy; preserve stale data only when labeled; avoid silent failure for user actions.
28 [P2][confirmed] Several UI features persist goals/consent in localStorage/sessionStorage without account or room lifecycle semantics. Evidence: TargetCompanyTracker.tsx, RoomLobbyPage.tsx and RoomArenaPage.tsx. Correct: server-sync account preferences; scope exam consent to room instance/version; clear on sign-out/room reset; don't make local storage authoritative.
29 [P2][verify] Long page files and broad `any` use complicate review and UI state. Evidence: InterviewPage.tsx, RoomArenaPage.tsx, AdminPage.tsx, CommandPalette.tsx. 30 [P2][verify] Visualizer playback and Monaco editor need reduced-motion, screen-reader and touch alternatives. Evidence: components/learn/visualizations and room/editor pages. Correct: textual step descriptions, labeled controls, keyboard/touch operation, reduced-motion behavior and non-editor fallback for read-only code.
31 [P2][confirmed] SPA index has one canonical and metadata set for every route; authenticated routes are client-rendered. Evidence: apps/web/index.html, apps/web/vercel.json. Correct: keep public landing SEO claims accurate; give public help/feedback unique metadata or prerender them; noindex private routes; add sitemap/robots if public content is intended to rank.
32 [P2][verify] Asset/fonts load from several external origins and voice WASM files are copied into build even though voice page is disabled. Evidence: apps/web/index.html, vite.config.ts, App.tsx. Correct: measure bundle/network waterfall, self-host or consolidate fonts where useful, remove dormant voice assets until enabled, preserve required COOP/COEP compatibility.

BACKEND, OPERATIONS AND QUALITY
33 [P1][confirmed] Server tests require GROQ_API_KEY at import time. `bun test apps/server/src/__tests__` without a key produced 89 pass, 1 fail, 1 error from lib/groq.ts; rerun with a dummy test key produced 106 pass, 0 fail (the logged "Neon DB connection timeout" is an intentional fail-closed test case). Correct: inject/mocks for Groq clients; instantiate lazily with clear runtime config validation; run hermetic tests without production secrets.

35 [P1][confirmed] Deployment Docker image uses Bun 1.2 while current local Bun is 1.3.13, and packageManager says 1.2.0. Evidence: Dockerfile/package.json/local runtime. Correct: pin and test one runtime version across local, CI and production; use frozen lockfile and build smoke check.
36 [P1][verify] Prisma package versions mix client/prisma 6.x with adapter/config 7.x. Evidence: packages/db/package.json. Correct: align compatible versions after checking actual package use; generate client and run migrations against disposable DB in CI.
37 [P1][confirmed] No root test/lint/typecheck scripts or visible CI workflow were found; web test script exists and server tests run ad hoc. Evidence: package.json, apps/*/package.json, repository scan. Correct: add reproducible root quality commands and CI gates for typecheck, lint, web/server tests, build, Prisma validation/migrations and a small API smoke suite.
38 [P1][verify] Health endpoint reports basic status but should distinguish process liveness from DB/Redis/Judge readiness. Evidence: apps/server/src/index.ts /health and render.yaml healthCheckPath. 39 [P2][verify] API and WebSocket handlers log directly and sometimes include user identity, raw errors or request URL. Evidence: index.ts, roomSocket.ts, feedback.ts. Correct: structured logger with request ID, redaction for tokens/PII/query strings, consistent error envelope, bounded logs and metrics.
40 [P2][verify] Missing pagination on admin/users/interviews/history/submissions and other list endpoints may grow costly. Evidence: apps/server/src/routes/admin.ts, interview.ts, rooms.ts. 41 [P2][verify] `db:push` is a prominent root command while production schema uses migrations. Evidence: root package.json, packages/db/prisma/migrations. Correct: deploy reviewed migrations via `migrate deploy`; keep push for local prototyping only; verify backup and rollback path.
42 [P2][confirmed] Frontend production build succeeds but emits a >500 kB chunk warning: largest JS chunk is 574.95 kB (178.21 kB gzip), and several feature chunks exceed 100 kB. Evidence: `bun run --cwd apps/web build` output. Correct: inspect bundle composition, split shared heavy libraries where it improves initial load, and measure route-level network cost before optimization.
